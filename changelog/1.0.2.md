# ✨ DreamHud v1.0.2 — Icon & Font Polish Update

> *Released on*: November 2025  
> *Codename*: **"Crystal Glyphs"** 🔮

---

## 🌙 Overview

This update refines DreamHud’s icon rendering system and introduces a cleaner, dedicated implementation for glyph-based HUD elements.  
The new `IconElement` is now more predictable, more flexible, and fully aligned with DreamHud’s font pipeline.

v1.0.2 contains no breaking changes and serves as a visual/API polish update in preparation for the feature-focused **v1.1.0** milestone.

---

## 🆕 New & Improved

### 🎨 **Refactored `IconElement`**
- Replaced the previous cloned/modified `TextElement` implementation.
- `IconElement` is now a fully independent element designed solely for rendering glyph icons.
- Added explicit fields:
  - `icon` — the glyph or character to render
  - `width` — fixed pixel width reported by the element
- Improved font resolution behavior:
  - When `fontString` is set → maps to `<namespace>:font_<name>`
  - Otherwise falls back to the explicit `Key` font

The element is now stable, consistent, and suitable for all custom font glyphs (hearts, bullets, markers, indicators, etc.).

---

## 🛠️ Internal Improvements

### 🧹 General cleanup
- Improved clarity of internal logic inside `toComponent()`.
- Unified how decorations, colors, and shadows are applied.
- Minor refactoring to improve readability and consistency across the codebase.

---

## 🔧 Fixes & Stability

- Fixed font selection inconsistencies that occurred when only one of `font` or `fontString` was provided.
- More robust fallback behavior when no font is explicitly defined.

---

## 🧠 Developer Notes

- **No API changes.**  
  DreamHud v1.0.2 remains fully backward-compatible with v1.0.0 and v1.0.1.
- `IconElement` is now the recommended approach for all glyph-driven UI elements.
- Icon width must still be provided manually to maintain pixel-perfect rendering.
